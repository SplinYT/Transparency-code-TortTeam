# ЗакупКонтроль

Авторы: Вафин О.Э. и Юрьев В.О., ПРО-305Б, УУНиТ.
Направление № 2: выявление и мониторинг коррупционных рисков в госзакупках.

## Запуск в Windows

1. Скачайте репозиторий через Code → Download ZIP и полностью распакуйте архив.
2. Установите Python 3.10 или новее, если он ещё не установлен.
3. Откройте папку prototype и запустите start_windows.bat.
4. В браузере откройте http://127.0.0.1:8765, если он не открылся автоматически.
5. Нажмите «Загрузить демоданные».

Альтернатива в PowerShell из папки prototype: `py -3 server.py`.
Linux/macOS: из папки prototype выполните `python3 server.py`.
Внешние Python-пакеты, интернет и ключи API не нужны. Для остановки: Ctrl+C.
Если порт 8765 занят, закройте ранее запущенный экземпляр программы.
Проверены вычислительная часть, HTTP API и полный браузерный сценарий: загрузка данных, фильтр, карточка, решение и экспорт JSON. Запуск Windows отдельно не проверялся.

## Сценарий демонстрации

Загрузите demo.csv, проверьте итог 40 закупок / 24 сигнала. Выберите фильтр «Требуют проверки». Откройте Z001: 100 баллов, четыре причины. Выберите «Запросить документы», введите основание, сохраните решение, экспортируйте JSON. Решения остаются в памяти вкладки до новой загрузки данных или перезагрузки страницы. Для сохранения результата выгрузите отчёт.

Без браузера: `py -3 demo_console.py` (Linux/macOS: `python3 demo_console.py`). Создаётся demo_report.json. Решение аналитика в консольном сценарии задано заранее для демонстрации.

## Ограничения

Данные исключительно синтетические. Пороги эвристические, не юридические. Сигнал не доказывает нарушение. Нет интеграции с реальными реестрами, идентификации лиц, авторизации, базы решений и многопользовательского режима. Доля поставщика относится только к загруженному набору, поэтому для реального анализа нужна сопоставимая и полная выборка. Не публикуйте локальный HTTP-сервер в общей сети.
